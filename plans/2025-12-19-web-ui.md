# Web UI Plan

## Goal
First visual UI: `./cells serve <file>` → opens HTML Canvas spreadsheet viewer on port 8888.

## Design Decisions

### Quadtree for Spatial Indexing (not 2D grid)

**Why quadtree?**
- Cells already have positions via `col.position` and `row.position`
- Sparse data: only store cells that exist
- O(log n) viewport queries instead of copying to a 2D grid
- No data duplication between model and render layer

**Max depth for Excel-size grid:**
- 1,048,576 rows (2^20) × 16,384 columns (2^14)
- Quadtree depth = max(log₂(rows), log₂(cols)) = 20 levels
- **Maximum 20 jumps** to find any cell

**Quadtree operations:**
| Operation | Complexity |
|-----------|------------|
| Insert cell | O(log n) |
| Query viewport | O(k + log n) where k = cells in viewport |
| Move cell | O(log n) remove + O(log n) insert |

### Web Server

Use **cpp-httplib** (header-only, ~4k lines):
- HTTP/1.1 support
- Static file serving
- Simple API routing
- No external dependencies

### Frontend Stack

**Minimal: Pure HTML + Canvas + Vanilla JS**
- No React, no bundler
- Single `index.html` with embedded CSS/JS
- Canvas for grid rendering
- Input overlay for cell editing

## API Design

### GET /api/sheet-info
Returns sheet metadata for initial setup.

```json
{
  "name": "Sheet1",
  "rowCount": 100,
  "colCount": 26,
  "defaultColWidth": 100,
  "defaultRowHeight": 24
}
```

### GET /api/viewport?x1=0&y1=0&x2=50&y2=100
Query cells visible in position range.

**Formula display:** Formulas are stored with **cell UUID** refs (not col+row UUIDs).
The API converts them to A1 notation for display.

Format: `[col_flag][row_flag]cellUUID` where `$` = absolute, `~` = relative

| Internal (Cell UUID) | Display (A1) | Meaning |
|----------------------|--------------|---------|
| `$$Kj7mXp2Q` | `$A$1` | Both absolute |
| `$~Kj7mXp2Q` | `$A1` | Col absolute, row relative |
| `~$Kj7mXp2Q` | `A$1` | Col relative, row absolute |
| `Kj7mXp2Q` | `A1` | Both relative (`~~` omitted) |

Resolution: `cellId` → `Cell` → `(cell.colId, cell.rowId)` → axis positions → A1 notation.

**Note:** Current `RefConverter` uses `$colId$rowId` format - needs update to use cell UUIDs.

```json
{
  "cells": [
    { "id": "Kj7mXp2Q", "col": 0, "row": 0, "value": "Hello", "type": "s" },
    { "id": "fR3pK7wN", "col": 1, "row": 0, "value": "42", "type": "n" },
    { "id": "pQ8nL3mX", "col": 0, "row": 1, "formula": "=A1+10", "type": "f", "display": "52" }
  ],
  "columns": [
    { "id": "cA", "pos": 0, "width": 100, "name": "" },
    { "id": "cB", "pos": 1, "width": 120, "name": "Revenue" }
  ],
  "rows": [
    { "id": "r1", "pos": 0, "height": 24, "name": "" },
    { "id": "r2", "pos": 1, "height": 24, "name": "" }
  ]
}
```

### POST /api/cell/:id (future)
```json
{ "value": "new value" }
```

## Implementation Plan

### Phase 0: RefConverter Update (prerequisite)
Current format uses `$colId$rowId` (col/row UUIDs). Update to use cell UUIDs:

Format: `[col_flag][row_flag]cellUUID` where `$`=absolute, `~`=relative, `~~` omitted
- `$$UUID` → `$A$1`
- `$~UUID` → `$A1`
- `~$UUID` → `A$1`
- `UUID` → `A1`

Tasks:
1. Update `RefConverter` to parse new format
2. Add cell lookup: Sheet context to resolve `cellId` → `Cell` → `(colId, rowId)`
3. Update formula serialization to use cell UUID format
4. Update tests

### Phase 1: Quadtree (core)
1. Create `core/cells/quadtree.h` - Quadtree spatial index
2. Implement insert, remove, query operations
3. Unit tests for viewport queries

### Phase 2: HTTP Server (cli)
1. Add cpp-httplib to third_party
2. Create `apps/cli/server.h/.cc` - HTTP server wrapper
3. Add `serve` command to main.cc
4. Implement `/api/viewport` endpoint
5. Implement `/api/sheet-info` endpoint

### Phase 3: Web Frontend
1. Create `apps/cli/web/index.html` - Single-file UI
2. Canvas rendering: grid lines, cell backgrounds, text
3. Scroll handling with viewport API requests
4. Column/row headers (A, B, C... and 1, 2, 3...)
5. Cell selection highlight

### Phase 4: Cell Editing (future)
1. Input overlay positioned over selected cell
2. POST to update cell value
3. Re-render affected cells

## Canvas Rendering Strategy

1. **Fixed canvas size** = viewport size (no virtual canvas)
2. **Scroll offset** stored in JS state
3. **On scroll**: request new viewport data, redraw entire canvas
4. **Headers**: render in separate rows/columns at edges
5. **Selection**: highlight cell with border

**Drawing order:**
1. Clear canvas
2. Draw grid lines
3. Draw column headers (A, B, C...)
4. Draw row headers (1, 2, 3...)
5. Draw cell values (text, aligned)
6. Draw selection border

## Performance Considerations

- **Debounce scroll** requests (16ms)
- **Request overscan** (extra 10 rows/cols beyond viewport)
- **Cache viewport data** until scroll exceeds overscan
- **Batch text rendering** with same style

## Open Questions

1. **Embedded vs. external HTML?**
   - Embedded in binary (no external files)
   - Or serve from filesystem (easier development)
   → Start with filesystem, add embedding later

2. **Column width storage?**
   - Currently Axis has `size` field
   - Quadtree queries should include axis info
   → Already supported

3. **Formula display values?**
   - Convert cell UUID refs to A1 notation for display
   - `formula` field shows A1 notation (e.g., `=A1+10`)
   - `display` field shows computed value (when formula engine exists)
   → For now: display formula text in A1 notation, computed value later

4. **RefConverter update needed?**
   - Current: `$colId$rowId` format (18 chars)
   - New: `[col][row]cellUUID` format (`$$`, `$~`, `~$`, or bare UUID)
   - Cell UUID lookup: `cellId` → `Cell` → `(colId, rowId)` → positions
   → Update RefConverter in Phase 0
